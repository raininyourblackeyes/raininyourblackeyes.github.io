During the first few practicals, I received feedback mainly about the basic structure of my code. My code could run and produce the required results, but some parts were not very easy to read. For example, some variable names were too simple, and I did not always add enough comments to explain what each part of the code was doing. I was also reminded to make the output clearer, so that the user could understand the result more easily.

In the later practicals, I received more feedback from my partner and classmates. Their feedback focused more on code readability, special cases, and small errors. For example, they suggested that I should add comments for important steps, make the logic easier to follow, and consider unusual input or results, such as negative numbers, wrong input format, or impossible population values in the simulation. They also helped me notice some small problems, such as unclear output, repeated code, or results that did not fully make sense biologically or mathematically.

Based on this feedback, I improved my code in several ways. I added more comments, used clearer variable names, and tested my code step by step. When errors appeared, I used print statements to check intermediate values and find where the problem happened. I also tried to think more carefully about special cases before running the program. Through these practicals, I learned that writing code is not only about making it work, but also about making it clear, readable, and reliable.
